# TalentMind AI Competency Evaluation & Scoring Rubric

## 1. Standardized 5-Point Competency Scale

All candidate evaluations in TalentMind AI adhere to a standard 1.0 to 5.0 score rubric grounded exclusively in observable evidence:

| Score | Rating Level | Operational Definition | Required Evidence |
|---|---|---|---|
| **5.0** | **Expert / Mastery** | Demonstrates deep mastery, architectural foresight, edge-case awareness, and clear communication. | Candidate provides production-tested architectural tradeoffs, handles nuances without prompting, and demonstrates exceptional clarity. |
| **4.0** | **Proficient / Strong** | Meets all standard requirements for the role. Solid theoretical grounding and practical execution. | Candidate answers correctly, provides relevant real-world examples, and passes primary test assertions. Minor guidance needed for complex edge cases. |
| **3.0** | **Developing / Basic** | Demonstrates foundational comprehension but exhibits knowledge gaps in complex scenarios or edge cases. | Candidate understands basic concepts but struggles with optimization, microservices scaling, or algorithmic time complexity. |
| **2.0** | **Incomplete / Weak** | High-level conceptual familiarity with noticeable misconceptions or failing test cases. | Candidate cannot articulate core mechanisms (e.g. difference between Promises and Observables) or fails standard test cases. |
| **1.0** | **Unsatisfactory / Absent** | Answer is absent, off-topic, or completely incorrect. | Candidate provides no evidence addressing the required competency. |

---

## 2. Evaluation Schema & Quote Grounding

Every AI evaluation entry generated by the system contains the following structured attributes:

```typescript
interface EvaluationResult {
  competency: string;             // e.g. "Frontend Architecture & Angular Signals"
  score: number;                  // Machine score from 1.0 to 5.0
  maxScore: number;               // Standard max (5.0)
  confidence: number;             // Confidence coefficient (0.0 - 1.0)
  summary: string;                // Concise, objective synthesis of candidate's answer
  quoteEvidence: string[];        // 1-3 direct verbatim quotes from candidate's answer
  strengths: string[];            // Bullet points of observed strengths
  gaps: string[];                 // Identified knowledge gaps or questions for follow-up
  isOverridden: boolean;          // Human override flag
  humanScore?: number;            // Recruiter-adjusted score
  overrideReason?: string;        // Mandatory justification note
}
```

---

## 3. Human Override Audit Trail

To preserve legal compliance and ethical accountability:
1. When a recruiter overrides an AI score, `isOverridden` is marked `true`.
2. The `overrideReason` must contain at least 10 characters explaining the non-discriminatory basis of the change.
3. An immutable audit record is committed to the database with:
   - Recruiter User ID & Full Name
   - Previous Machine Score & New Human Score
   - Timestamp & Justification Text
